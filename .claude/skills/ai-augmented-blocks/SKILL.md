# AI 기술 자료 참조 블록

이 스킬은 다음에 대한 **AI 기술 자료** 아코디언 블록을 생성하고 관리합니다.
Adobe Journey Optimizer 설명서(`journey-optimizer.en`). 블록은 구조화되어 있고
문서 페이지에 현지화되지 않은 컨텍스트가 추가되어 AI 어시스턴트가 다음에 대한 질문에 답변합니다.
Journey Optimizer을 보다 정확하게 표현합니다.

각 블록은 **현지화하지 않음 포함**(번역되지 않음)으로 저장되고 가져옵니다
`{{$include}}`을(를) 사용하여 페이지에 삽입합니다. 블록에 해당 페이지에서 파생할 수 있는 **개의 팩트만 포함되어 있습니다.
body** — 다른 페이지, 일반 제품 지식 또는 HTML 주석에서 가져온 것이 없습니다.

> **항목을 생성하기 전에 참조 파일을 읽습니다.** 여기에는 실제 규칙이 포함되어 있지만
> 요약:
> - `references/generation-spec.md` — 블록 구조입니다. 섹션별로 고정 열림
>   컨텐츠 규칙 및 모든 정밀도 규칙(엄격한 제한 및 권장 제한, 유효성 검사 모드)
>   상태 레이블, 수축 없음, 금지 단어 목록).
> - `references/verification-round.md` — **필수** 독립적인 적대적 팩트 확인
>   여기가 최종 품질게이트입니다 이는 선택 사항이 아니며 건너뛸 수 없습니다.
> - `references/git-jira-tracking.md` — 분기/커밋/PR 흐름(작성자에게 질문한 후 열기
>   PR; **병합 안 함**) 및 DOCAC JIRA 추적.

## 이 스킬이 적용되는 경우

- **새 페이지**&#x200B;이(가) `help/using/<folder>/`에 만들어져 →을 생성합니다.
- **기존 페이지가 변경됨**→ 해당 블록이 페이지 본문에서 이동했는지 확인하고 업데이트하십시오.
- **추가, 업데이트, 확인 또는 감사를 요청함** AI 기술 참조/AI 증강 블록.

## 범위 및 제외

- `help/using/<folder>/` 아래의 **범위:**&#x200B;페이지.
- **범위를 벗어남 — 여기에 블록을 추가하지 않음:**
  - `help/rp_landing_pages/`(시작/랜딩 페이지) — 작성자 규칙에 의해 제외됩니다.
  - 가상 탐색/링크 허브, 인덱스 전용 페이지 및 거의 비어 있는 페이지. 페이지가 비어 있는 경우
    실질적인 개념이 없는 링크 목록입니다. **건너뛰고 이유** — 차단을 강제하지 마십시오.
  - 릴리스 노트(`help/using/rn/`, 릴리스 노트 페이지).
- 페이지가 충분히 실질적인지 의심스러울 때 콘텐츠별로 판단합니다. 진짜인지 판단하십시오.
개념, 제한 또는 용어를 다루십시오. 다른 곳만 가리키면 건너뜁니다.

## 워크플로

**한 번에 하나의 폴더(또는 하나의 페이지)에서 작업합니다**. 관련 없는 폴더를 하나의 분기로 일괄 처리하지 마십시오.

### 1 — 대상 및 모드 결정

작성자에게 요청(또는 요청/열린 파일에서 유추)하여 처리할 페이지를 찾고
페이지당 모드:

- **CREATE** — 페이지에 `{{$include .../ai-augmented-<page>.md}}` 줄이 없고 기존 줄이 없습니다.
`+++ AI Knowledge Reference`개 블록→ 인라인으로 새 블록을 생성합니다.
- **업데이트** — 페이지에 이미 차단이 있습니다. 페이지 본문 해시를 계산하고 해시를
  포함된 동기화 주석의 `source-hash`(아래 참조). 서로 다른 경우 페이지가 →
  블록을 재생성/새로 고칩니다. 일치하는 경우 블록은 현재 → 건너뛰기입니다(&quot;최신&quot; 보고).
- **마이그레이션** — 페이지에 *인라인* `+++ AI Knowledge Reference` 블록이 있습니다(아직 아님).
외부화) →을 현지화하지 않음(do-not-localize)으로 이동하려면 다음을 포함하고으로 대체합니다. `{{$include}}`
line, 컨텐츠 충실도 유지.

어디서나 동일한 방식으로 페이지 본문 해시를 계산합니다(동기화 댓글 및 드리프트 검사에 사용됨).

```bash
md5 -q help/using/<folder>/<page>.md | cut -c1-8
```

페이지를 편집하기 전에 **이전**&#x200B;을(를) 계산(블록이 있을 때 해시가 본문을 그대로 포함)
생성됨). Linux에서는 `md5sum help/using/<folder>/<page>.md | cut -c1-8`을(를) 사용합니다.

### 2 - 블록 생성(또는 새로 고침)

모든 페이지에 대해 정확히 `references/generation-spec.md`을(를) 팔로우합니다. 주요 불변:

- 두 개의 **고정된 여는 단락**, 축어, 바이트 단위(사용하지 않음).
- 섹션 순서: **TL;DR, 의도, 용어집, 보호 기능, 용어, FAQ**.
- 모든 클레임은 페이지 본문에서만 적용됩니다. 수축이 없습니다. 숫자의 자격을 다음으로 설정
  페이지에서 적용/권장 사항을 사용하는 경우 `(hard limit)` / `(recommended)` **전용**
  단어, 그렇지 않은 경우 한정자가 없습니다. 페이지의 정확한 유효성 검사 모드 및 상태 레이블을 사용합니다.
  `[!UICONTROL ...]`/`[!DNL ...]` 문자열을 약어로 유지합니다. 금지된 부정확성을 절대 사용하지 마세요
  용어가 페이지에 축어적으로 표시되지 않는 경우.

**파일 포함** — `help/_includes/do-not-localize/<folder>/ai-augmented-<page>.md`
필요한 경우 `<folder>` 하위 디렉터리를 만들고 `-`(으)로 중첩된 페이지 경로를 병합합니다.

```
---
title: AI Knowledge Reference
---
# AI Knowledge Reference

+++ AI Knowledge Reference

[fixed opening paragraphs + the six sections]

+++

<!-- ai-section-version: 1 | source-hash: <first 8 chars of md5 of the page body> -->
```

**페이지 편집** — 마지막 내용 줄과 빈 줄을 정확히 한 줄 추가합니다.
(페이지의 다른 항목은 터치하지 마십시오):

```
{{$include /help/_includes/do-not-localize/<folder>/ai-augmented-<page>.md}}
```

UPDATE에서 포함 파일만 편집하고 추적하려면 `ai-section-version`을(를) 범프
revisions); 페이지의 `{{$include}}` 줄은 일반적으로 동일하게 유지됩니다. `source-hash` 새로 고침 대상:
블록이 페이지와 다시 일치하면 현재 페이지 본문 해시가 표시됩니다.

`references/generation-spec.md`에서 **자체 검사** 실행(3단계 클레임 확인 +
사후 생성 체크리스트)를 참조하십시오. 여기는 2번게이트 1번입니다

### 3 — 독립 검증 라운드 (필수 최종 게이트)

이 단계는 작성자가 특별히 요구하는 단계입니다. **각 블록이 유효한지, true인지 확인하고,
명확하지 않습니다.** *새로 고침, 독립* 패스로 실행하십시오.
에서는 페이지 본문과 블록만 볼 수 있으며 블록이 작성된 방법에 대한 기억은 없습니다.
`references/verification-round.md`. 모든 클레임을 다시 점검하고 잘못 표시된 한도도 낮추고
동의어와 혼동하지 않음 오류를 수정하고 페이지에 기반을 두지 않은 모든 오류를 제거합니다. 적용
계속하기 전에 포함 파일에 대한 모든 수정 사항. 여기는 2번 게이트 2번이라서 빼먹을 수 없습니다

### 4 - 구조적 스윕

커밋하기 전에 구조 및 위생을 위해 모든 블록을 쓸어냅니다( 의 스윕 코드 조각 참조).
`references/git-jira-tracking.md`): 앞면 문제 + `# AI Knowledge Reference` 제목,
`+++ … +++`개 펜스, 고정된 여는 단락, 동기화 댓글, 수축 없음(제외)
축어 `[!UICONTROL ...]`) 및 페이지에 일치하는 `{{$include}}` 줄이 있습니다.

### 5 - JIRA에서 추적한 다음 PR에 대해 묻습니다(병합되지 않음).

`references/git-jira-tracking.md` 팔로우:

1. JIRA 작업(`DOCAC-<key>`)에 대해 이름이 지정된 분기에서 커밋하고 `main`에서는 커밋하지 않습니다. 확인
커밋이 `main`이(가) 아닌 분기에 랜딩되었습니다(`origin/main`보다 1번 앞에 커밋).
2. DOCAC 작업 업데이트: 변경 사항 + 확인 결과를 포함하는 주석, 수정 설정
버전을 만든 후 팀의 프로세스에 따라 전환합니다.
3. **작성자에게 끌어오기 요청을 원하는지 물어봅니다.** 예라고 하면 하나만 열어주세요.
4. **병합 안 함.** 이러한 PR은 사람의 검토를 위한 것입니다. 병합은 항상 작성자의 요구입니다.

### 6 — 보고서

페이지당 보고서: 생성됨/업데이트됨/마이그레이션됨/건너뜀(+ 이유), 확인 결과
(정리 또는 수정됨, 수정 사항 포함), JIRA 작업 및 PR 링크(열린 경우).

## 이 스킬을 실행하는 작성자를 위한 참고 사항

- 블록은 특정 시점의 페이지 본문의 **미분**&#x200B;입니다. 블록의 일부로 처리하십시오.
페이지를 가리키도록 업데이트하는 중입니다. 가드레일, 제한, 상태 레이블 또는
유효성 검사 모드에서 블록을 동일한 변경 내용으로 업데이트합니다.
- JIRA 및 PR 단계는 회사 JIRA 및 GitHub에 액세스해야 합니다. 그게 없으시면
액세스, 블록을 계속 생성 + 확인하고 로컬에서 변경 사항을 엽니다. JIRA/PR 단계를 전달합니다.
할 수 있는 사람에게
- 이 기술은 리포지토리에 상주하므로 작성팀 전체가 하나의 프로세스를 공유합니다. 개선
개인 복사본을 보관하지 않고 여기에서 파일을 참조합니다.
