# 여정 테스트 및 유효성 검사 방법 선택 {#choose-validation-method}

>[!BEGINSHADEBOX]

**이 페이지에서:** 여정 시뮬레이션, 여정 테스트 모드 및 여정 시험 실행을 비교하고, 설계 중 빠른 반복부터 라이브 대상자에 대한 최종 실행 전 확인까지 여정을 작성하는 현재 단계에 맞는 항목을 알아봅니다.

>[!ENDSHADEBOX]

[!DNL Adobe Journey Optimizer]은(는) 여정이 활성화되기 전에 유효성을 검사하는 세 가지 방법을 제공합니다. 서로 다른 종류의 데이터를 사용하고, 빌드의 다른 단계에 적합하며, 서로 다른 실제 결과를 수반하므로 상호 교환이 불가능합니다. 차이점을 먼저 파악하면 빠른 시뮬레이션이 수행될 때 테스트 프로필을 만드는 데 시간을 소비하거나, 실제 받은 편지함에 계속 연락하거나 실제 아웃바운드 호출을 할 수 있는 경우 유효성 검사 단계가 완전히 &quot;안전&quot;하다고 가정하는 등 두 가지 일반적인 실수를 방지할 수 있습니다.

이 페이지는 여정 흐름 및 분기 논리의 유효성 검사에 중점을 둡니다. 콘텐츠 미리 보기, 이메일 렌더링 및 스팸 확인, A/B 실험 및 승인 워크플로를 포함한 테스트 및 승인 기능의 전체 그림은 [테스트, 유효성 검사 및 승인](../../rp_landing_pages/test-landing-page.md)을 참조하십시오.

## 유효성 검사를 처음 사용하십니까? 여기서 시작 {#quick-pick}

어떤 방법이 적용되는지 확실하지 않은 경우 다음 한 가지 질문에 답합니다.

* **여정을 계속 디자인하고 있으며 테스트 프로필을 만들지 않고 분기의 논리를 빠르게 확인하려고 합니다.** →0}여정 시뮬레이션&#x200B;](simulate-journey-gs.md)**을 사용합니다.**[
* **실제(지정된 테스트) 프로필을 사용하여 초안 여정의 논리를 단계적으로 수동으로 확인하려고 합니다.** →0}여정 테스트 모드&#x200B;](testing-the-journey.md)**를 사용합니다.**[
* **게시하려고 하는데 누구에게도 연락하지 않고 실제 프로덕션 대상자에 대해 예상 볼륨을 최종 검사하려고 합니다.** →0}여정 시험 실행&#x200B;](journey-dry-run.md)**을 사용합니다.**[

아직 확실하지 않습니까, 아니면 전체 사진을 원하시나요? 계속해서 읽어 보십시오. 각 방법은 아래에 자세히 설명되어 있습니다.

## 세 가지 유효성 검사 방법 {#validation-methods}

>[!BEGINTABS]

>[!TAB 여정 시뮬레이션]

**사용할 시기:** 여정 디자인 중 특히 기한 직전 또는 새 분기 또는 경로를 테스트할 때 빠르게 반복되며, 사용 사례에 적합한 테스트 프로필을 만드는 것이 비현실적일 때마다 지속적인 유효성 검사 방법으로 잘 작동합니다.

[여정 시뮬레이션](simulate-journey-gs.md)은(는) 임시 시뮬레이션된 여정을 사용하여 사용자의 테스트를 확인합니다. 실제 Adobe Experience Platform(AEP) 테스트 프로필이 전파될 때까지 생성하거나 기다릴 필요가 없습니다. 시뮬레이션된 사용자를 수동으로 생성하거나 AI가 여정에 필요한 테스트 이벤트를 자동으로 생성하고 적합한 시뮬레이션된 사용자와 일치시켜 여정을 초 단위로 트리거할 수 있습니다.

주요 역학:

* 시뮬레이션된 사용자는 AEP의 실제 프로필이 아닙니다. [인벤토리](simulate-journey.md#test-users)에 저장하여 매번 처음부터 새로 만드는 대신 향후 시뮬레이션에서 다시 사용할 수도 있습니다.
* 종료 기준, 동의 정책, 빈도/여정 제한, 옵트아웃/억제 및 방해 금지 시간은 평가되지 않습니다.
* 사용자 지정 작업 및 외부 데이터 소스 호출은 여전히 실제 아웃바운드 호출을 수행하지만 조롱을 받지 않습니다.

>[!IMPORTANT]
>
>시뮬레이션은 프로덕션과 동일한 게재 파이프라인을 사용하여 시뮬레이션된 사용자(예: 자신의 이메일 주소)에 구성된 [실행 주소](simulate-journey.md#test-users)(이메일, 전화, 푸시 토큰)에 실제 메시지를 보냅니다. 실제 고객에게 연락하거나 라이브 프로필 데이터를 업데이트하지 않지만 메시지 자체는 진짜입니다.

**완벽한 대상:** AEP 테스트 프로필 전파를 기다리지 않고 새 분기(예: 두 개의 새 의사 결정 정책 경로)를 확인하는 중입니다.

➡️ [여정 시뮬레이션 시작](simulate-journey-gs.md) | [여정 시뮬레이션](simulate-journey.md)

>[!TAB 여정 테스트 모드]

**사용할 시기:** 분기 및 메시지 논리를 단계별로 수동으로 확인하고, 지정된 테스트 프로필이 초안 여정을 통과합니다.

[여정 테스트 모드](testing-the-journey.md)를 사용하면 영구 [AEP 테스트 프로필](../audience/creating-test-profiles.md)을 사용하여 초안 여정의 유효성을 검사할 수 있습니다. 프로덕션 대상이 여정을 터치하기 전에 인터페이스에서 이벤트를 수동으로 실행하여 분기 논리 및 메시지 게재 메커니즘이 설계된 대로 작동하는지 확인합니다.

주요 역학:

* 실시간 고객 프로필에서 &quot;테스트 프로필&quot;로 플래그가 지정된 프로필만 여정 테스트 모드에서 여정에 들어갈 수 있습니다.
* 여정 테스트 모드는 개인이 테스트 프로필인지 AEP에서 확인해야 하므로 [네임스페이스](../audience/get-started-identity.md)를 사용하는 초안 여정에 대해서만 사용할 수 있습니다.
* 단일 테스트 세션 중에는 최대 100개의 테스트 프로필이 여정에 들어갈 수 있으며 API를 통해 외부 시스템이 아닌 인터페이스에서만 이벤트를 실행할 수 있습니다.
* 여정 테스트 모드를 비활성화하면 여정에 들어간 모든 프로필이 제거되고 보고가 지워집니다.

>[!IMPORTANT]
>
>여정 테스트 모드는 프로덕션과 동일한 게재 파이프라인을 사용하여 테스트 프로필의 실제 받은 편지함에 실제 메시지를 보냅니다. 실제 고객에게는 연락하지 않지만 &quot;건식&quot; 시뮬레이션도 아닙니다. 테스트 프로필에서 사용자가 제어하는 주소를 사용하도록 하십시오.

**문제점:** 새 AEP 테스트 프로필을 만들고 전파하는 데 시간이 소요됩니다. [여정 시뮬레이션](simulate-journey-gs.md)은(는) 테스트 프로필이 전혀 필요 없는 빠른 대안을 제공합니다. 프로필이 전파될 때까지 기다리는 동안뿐만 아니라 사용 사례에 적합한 테스트 프로필을 만드는 것은 비현실적입니다.

➡️ [여정 테스트](testing-the-journey.md)

>[!TAB 여정 시험 실행]

**사용 시기:** 게시하기 직전에 최종 프로덕션 사실적 검사입니다.

[여정 시험 실행](journey-dry-run.md)은(는) 실제 고객에게 연락하거나 프로필 정보를 업데이트하지 않고 실제 프로덕션 대상 및 세분화 데이터에 대해 여정을 실행하는 특수 여정 게시 모드입니다. 여정은 라이브 여정과 같이 활성화되며, 프로필은 프로덕션에서와 동일하게 분기 및 노드를 통해 이동되지만, 이메일, SMS 및 사용자 지정 작업과 같은 [작업 노드](about-journey-activities.md)는 무시됩니다.

주요 역학:

* 는 실제 프로덕션 대상을 사용하므로 실제 도달 및 타겟팅을 규모에 맞게 표시합니다(예: 전체 분기가 예기치 않게 0의 프로필을 받는 버그 잡기).
* 각 활성화 시 대기 활동을 비활성화하여 지표가 더 빨리 돌아오도록 하고 외부 데이터 소스 호출을 비활성화하여 여정이 완전히 고립된 상태를 유지하도록 선택할 수 있습니다.
* 현재 **제한된 가용성** 기능이며 시간이 지남에 따라 전역적으로 롤아웃됩니다.

**완벽한 대상:** 여정 라이브를 전환하기 바로 전에 예기치 않게 분기에 도달하지 않는 잘못된 조건 노드 또는 대상자와 같은 문제를 포착합니다.

➡️ [여정 시험 실행](journey-dry-run.md)

>[!ENDTABS]

## 어떤 방법을 사용해야 합니까? {#decision-guide}

간단한 질문으로 시작하십시오. 사용 사례에 맞는 테스트 프로필이 이미 있습니까? 그렇다면 **여정 테스트 모드**&#x200B;를 사용하여 단계별 유효성을 검사할 수 있습니다. 그렇지 않은 경우 — 또는 이 특정 사용 사례에 대해 만들 수 없는 경우 — **여정 시뮬레이션**&#x200B;을 통해 대신 몇 초 만에 유효성 검사를 받을 수 있습니다.

이러한 선택 외에, 답은 대개 다음 질문 하나로 귀결됩니다. *프로덕션에 얼마나 근접해야 이 테스트가 필요합니까?*

여전히 **여정 디자인을 반복** — 새 분기를 테스트하고 기한 기준으로 작업하는 경우 **여정 시뮬레이션**&#x200B;을 사용하여 여정 논리의 유효성을 검사하십시오. 실제 프로필이 필요하지 않고 초 단위로 실행될 수 있으며, 사용 사례에 적합한 테스트 프로필을 만드는 것이 실용적이지 않을 때마다 빌드 후기에도 유효한 선택 사항이 유지됩니다. 시뮬레이션된 사용자에 구성된 실행 주소로 실제 메시지를 전송한다는 것만 기억하십시오.

**분기 및 메시지 논리를 단계별로 수동으로 확인**&#x200B;해야 하며 AEP 테스트 프로필을 만들거나 재사용할 의지가 있는 경우 **여정 테스트 모드**&#x200B;를 사용하십시오. 해당 테스트 프로필의 실제 받은 편지함에 실제 메시지를 전송한다는 것만 기억하십시오.

**게시**&#x200B;를 앞두고 있으며 누구와도 연락하거나 프로필 데이터를 변경하지 않고 실제 프로덕션 대상에 대해 예상 볼륨을 최종 검사하려는 경우 **여정 시험 실행**&#x200B;을 사용하십시오.

>[!TIP]
>
>**어디서부터 시작할지 알 수 없습니까?** 대부분의 팀은 빌드하는 동안 **여정 시뮬레이션**&#x200B;을 사용한 다음 게시하기 직전에 **여정 시험 실행**&#x200B;을 사용합니다. 시뮬레이션된 테스트 모드가 아닌 실제 테스트 프로필을 사용하여 분기 논리를 수동으로 통과해야 하는 경우 **여정 테스트 모드**&#x200B;에 도달합니다.

| 방법 | 사용된 데이터 | 실제 메시지를 전송하시겠습니까? | 다음에 최적 |
|---|---|---|---|
| [여정 시뮬레이션](simulate-journey-gs.md) | 수동으로 생성되거나 자동 생성된 임시 시뮬레이션된 사용자 | 예 — 시뮬레이트된 사용자에 구성된 실행 주소로 | 실제 테스트 프로필 전달을 기다리지 않고 새 분기 또는 경로에서 빠른 반복 |
| [여정 테스트 모드](testing-the-journey.md) | 영구 AEP 테스트 프로필 | 예 — 프로덕션 게재 파이프라인을 사용하여 테스트 프로필의 실제 받은 편지함에 | 초안 여정에서 분기/메시지 논리 단계별 수동 확인 |
| [여정 시험 실행](journey-dry-run.md) | 실제 프로덕션 대상/데이터 | 아니요(우회된 작업) | 실제 대상자 도달, 타기팅 및 분기 논리에 대한 실제 실행 전 최종 확인 |

이러한 방법 중 실제 고객과 접촉하는 방법은 없습니다. 또한 프로필 데이터는 여정 테스트 모드에서 실행하는 데 사용되는 테스트 프로필(실제 고객 프로필이 아님)을 업데이트하는 경우를 제외하고 모든 경우에 그대로 유지됩니다.

## 피해야 할 일반적인 실수 {#common-mistakes}

* **여정 시뮬레이션이 완전히 &quot;안전하다고 가정합니다.** 가장 빠른 테스트 방법이지만 각 시뮬레이션된 사용자(일반적으로 받은 편지함)에 구성된 실행 주소로 실제 메시지를 전송합니다. 아무 것도 전송되지 않는다고 가정하지 마십시오.
* **여정 시뮬레이션이 수행될 때 AEP 테스트 프로필을 만듭니다.** 새 분기 또는 의사 결정 정책 경로의 유효성을 빠르게 검사해야 하는 경우 시뮬레이션은 테스트 프로필 전파 대기를 완전히 건너뜁니다. 실제 테스트 프로필이 필요한 경우 여정 테스트 모드를 저장합니다.
* **여정 테스트 모드를 &quot;시험&quot;으로 처리 중입니다.** 여정 테스트 모드 프로필은 프로덕션 게재 파이프라인을 통해 실제 메시지를 수신합니다. 테스트 프로필에서 사용자가 제어하는 주소만 사용하도록 합니다.
* **콘텐츠 또는 게재 문제를 포착하기 위해 여정 시험 실행이 필요합니다.** 시험 실행은 작업 노드를 완전히 무시합니다. 메시지 콘텐츠나 게재 방식이 아닌 대상 도달 및 분기 논리를 검증합니다. 이를 위해 시뮬레이션 또는 여정 테스트 모드 를 사용하십시오.
* **여정 테스트 모드에 대한 네임스페이스 요구 사항을 무시합니다.** 여정 테스트 모드는 네임스페이스를 사용하는 초안 여정에서만 작동합니다. 네임스페이스가 없으면 Journey Optimizer은 프로필이 테스트 프로필로 플래그가 지정되었는지 여부를 확인할 수 없습니다.

* 여정 테스트 모드는 네임스페이스를 사용하는 초안 테스트에만 사용할 수 있으며 세션당 최대 100개의 여정 프로필을 지원합니다
* 여정 테스트 모드 이벤트는 API를 통한 외부 시스템이 아닌 인터페이스에서만 실행할 수 있습니다.
* 여정 테스트 모드는 프로덕션 게재 파이프라인을 사용하여 프로필의 실제 받은 편지함에 실제 메시지를 보냅니다.
* 여정 테스트 모드를 비활성화하면 여정에 들어간 모든 프로필이 제거되고 해당 보고가 지워집니다
* 여정 시뮬레이션은 종료 기준, 동의 정책, 빈도/여정 제한, 옵트아웃/억제 또는 방해 금지 시간을 평가하지 않습니다.
* 여정 시뮬레이션의 사용자 지정 작업 및 외부 데이터 소스 호출은 조롱이 아닌 실제 호출입니다
* 여정 시뮬레이션은 실제 메시지를 보내지 않는 여정 드라이 실행과 달리, 프로덕션과 동일한 게재 파이프라인을 사용하여 시뮬레이션된 사용자에 구성된 실행 주소(이메일, 전화, 푸시 토큰)에 실제 메시지를 보냅니다
* 여정 시험 실행은 현재 제한된 가용성 기능이며 시간에 따라 전역적으로 롤아웃됩니다
* 여정 드라이 실행은 작업 노드(이메일, SMS, 사용자 지정 작업)를 우회하지만 여전히 실제 프로덕션 데이터를 사용하여 분기 및 노드를 통해 프로필을 라우팅합니다

* 정식 이름: 여정 시험 실행 — 변형: 시험 실행, 시험 실행 모드
* 혼동하지 마십시오: 여정 시뮬레이션(임시 시뮬레이션된 사용자, AEP 테스트 프로필이 필요하지 않음, 시뮬레이션된 사용자의 구성된 실행 주소에 실제 메시지 보내기) ≠ 여정 테스트 모드(영구 AEP 테스트 프로필, 해당 프로필의 실제 받은 편지함에 실제 메시지 보내기) ≠ 여정 Dry Run(실제 프로덕션 대상 데이터, 연락처 없음, 프로필 업데이트 없음, 작업 노드가 무시됨, 실제 메시지를 보내지 않음)

**FAQ:**

* **Q: 여정을 디자인하는 동안 어떤 유효성 검사 방법을 사용해야 합니까?** — 여정 시뮬레이션을 사용합니다. 실제 테스트 프로필이 필요 없고 몇 초 안에 실행되므로 빠른 반복에 이상적입니다.
* **Q: 여정 시뮬레이션에서 실제 메시지를 전송합니까?** — 예. 시뮬레이션은 프로덕션과 동일한 게재 파이프라인을 사용하여 시뮬레이션된 사용자(종종 테스터 자신의 주소)에 구성된 실행 주소(이메일, 전화, 푸시 토큰)에 실제 메시지를 전달합니다. 실제 고객에게 연락하거나 라이브 프로필 데이터를 업데이트하지 않지만 메시지 자체는 진짜입니다.
* **Q: 여정 테스트 모드에서 실제 전자 메일 또는 SMS를 전송합니까?** — 예. 여정 테스트 모드는 프로덕션과 동일한 게재 파이프라인을 사용하여 실제 메시지를 테스트 프로필의 받은 편지함에 전달합니다. 실제 고객에게는 연락하지 않지만 메시지 자체는 진짜입니다.
* **Q: 여정 시험 실행이 메시지를 전송합니까?** — 아니요. 드라이 실행은 이메일, SMS 및 사용자 지정 작업과 같은 작업 노드를 건너뛰므로 프로필은 메시지가 전송되지 않고 여정 논리를 통해 흐릅니다.
* **Q: 기한 전에 새 분기의 유효성을 빨리 검사해야 합니다. 어떤 메서드가 적합합니까?** — 여정 시뮬레이션. 실제 테스트 프로필을 미리 만들고 기다리는 대신 시뮬레이션 사용자를 온디맨드로 생성(또는 재고에 저장된 사용자를 재사용)합니다.
* **Q: 모든 사용자가 여정 시험 실행을 사용할 수 있습니까?** — 현재 시간이 지남에 따라 전역으로 롤아웃되는 제한된 가용성 기능입니다. 조직의 가용성을 확인하십시오.
* **Q: 외부 시스템에서 여정 테스트 모드 이벤트를 실행할 수 있습니까?** — 아니요. 여정 테스트 모드에서는 API를 통한 외부 시스템이 아닌 인터페이스에서만 이벤트를 실행할 수 있습니다.
