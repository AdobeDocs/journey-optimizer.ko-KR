# 여정 이벤트 작업 {#about-events}

>[!BEGINSHADEBOX]

**이 페이지에서:** 세 가지 이벤트 유형, 스키마 요구 사항, 키 제약 조건 및 사용 사례에 적합한 이벤트 유형을 선택하는 방법을 이해합니다.

>[!ENDSHADEBOX]

>[!CONTEXTUALHELP]
>id="ajo_journey_event_list"
>title="여정 이벤트"
>abstract="Journey Optimizer는 여정에서 특정 개인의 행동(예: 구매 또는 충성도 마일스톤)과 연계된 단일 이벤트, 글로벌 이벤트(예: 항공편 취소 또는 재고 업데이트)에 의해 트리거된 비즈니스 이벤트, 프로필이 대상자를 진입 또는 종료할 때 트리거된 대상자 선별 이벤트의 세 가지 유형 이벤트를 지원합니다. 이벤트를 사용하여 여정을 트리거하고 프로필에 맞는 올바른 액션을 조율합니다."

이벤트를 사용하여 여정을 개별적으로 트리거하여 여정에 들어갈 때 각 사용자에게 실시간 메시지를 전달합니다. 이벤트 구성에서 여정에서 예상되는 이벤트를 구성합니다. 여정의 각 단계에서 여러 이벤트를 사용할 수 있으며 여러 여정에서 같은 이벤트를 사용할 수도 있습니다.

이벤트 구성은 **필수**&#x200B;이며 데이터 엔지니어가 수행해야 합니다.

>[!IMPORTANT]
>
>* 이벤트를 구성하기 전에 **Journey Optimizer 관리자** 또는 **데이터 엔지니어** 역할, **실시간 고객 프로필**&#x200B;이 활성화된 XDM 스키마, 활성 스트리밍 끝점 및 올바른 샌드박스에 대한 액세스 권한이 있는지 확인하십시오.
>
>* 이벤트 요구 사항 및 제한 사항(스트리밍, 쿼리 서비스, 일괄 처리 수집)에 대해서는 [여정 보호 - 이벤트](../start/guardrails.md#events-g)를 참조하십시오.

**수행할 사람:**

| 작업 | 역할 |
| --- | --- |
| XDM 스키마 디자인 및 만들기 | 데이터 엔지니어 |
| 스트리밍 끝점 설정 | 데이터 엔지니어 |
| 단일 및 비즈니스 이벤트 구성(**관리 > 이벤트**) | 데이터 엔지니어 또는 관리자 |
| 여정에서 이벤트 사용 | 여정 실무자 |
| 대상 자격 이벤트 구성(캔버스에서 선택됨) | 여정 실무자 |

세 가지 유형의 이벤트를 구성할 수 있습니다. **단일 이벤트**, **비즈니스 이벤트** 및 **대상 자격 이벤트**.

## 단일 이벤트 {#unitary-events}

**단일** 이벤트가 사용자에 연결되어 있습니다. 개인의 비헤이비어(예: 제품 구매, 상점 방문, 웹 사이트 종료자 등)와 관련되어 있습니다. 해당 사용자와 관련하여 발생하는 상황일 수도 있습니다. 사용자가 충성도 점수 10,000점을 달성하는 등의 경우를 예로 들 수 있습니다. [!DNL Journey Optimizer]은 여정에서 이러한 이벤트를 수신하여 최적의 다음 작업을 조율합니다. 단일 이벤트는 규칙 기반 또는 시스템 생성 이벤트가 될 수 있습니다. [단일 이벤트를 만드는 방법을 알아봅니다](../event/about-creating.md).

**스키마 요구 사항:** 사용자 기반 기본 ID와 **실시간 고객 프로필**&#x200B;이 활성화된 XDM ExperienceEvent 스키마.

**예:** 고객이 장바구니에 항목을 추가하고 브라우저를 닫습니다. 장바구니 포기 이벤트가 실행되면 프로필이 실시간으로 여정에 들어가고 한 시간 후 복구 이메일을 받게 됩니다.

>[!NOTE]
>
>단일 여정은 재진입 가드레일을 포함합니다. 프로필 재진입은 여정 트리거 후 5분 동안 기본적으로 차단됩니다. 예를 들어 이벤트가 프로필에 대해 12:01에 여정을 트리거하고 다른 이벤트가 12:03에 도착하는 경우 해당 프로필에 대해 여정이 다시 시작되지 않습니다.

## 비즈니스 이벤트 {#business-events}

**Business** 이벤트가 특정 프로필에 연결되어 있지 않습니다. 예를 들어 뉴스 경고, 스포츠 업데이트, 비행 변경 또는 취소, 인벤토리 업데이트, 날씨 이벤트 등이 될 수 있습니다. 이러한 이벤트는 프로필에만 국한되지 않지만 특정 뉴스 주제를 구독하는 개인, 항공편 승객, 재고 부족 제품에 관심이 있는 쇼핑객 등 다양한 프로필에 관심을 가질 수 있습니다. 비즈니스 이벤트는 항상 규칙을 기반으로 합니다. 여정에서 비즈니스 이벤트를 삭제하면 **대상자 읽기** 활동이 바로 자동으로 추가됩니다. [비즈니스 이벤트를 만드는 방법에 대해 알아보세요](../event/about-creating-business.md).

**스키마 요구 사항:** 비사용자 기본 ID가 포함된 시계열 XDM 스키마와 `_id` 및 `timestamp` 필드가 채워졌습니다. 15분에서 최대 1시간까지 대상 내보내기 지연을 계획합니다.

**예:** 항공사가 항공편을 취소합니다. 비즈니스 이벤트가 실행되면 [!DNL Journey Optimizer]에서 영향을 받는 승객의 대상을 읽은 후 재예약 알림을 보냅니다.

## 대상자 선별 이벤트 {#audience-qualification-events}

프로필이 대상자에 들어오거나 나갈 때 **대상자 자격** 이벤트가 트리거됩니다. 예를 들어, 충성도 지출 임계값을 넘은 고객이 Gold Tier 대상자로 진입하면 해당 자격이 해당 프로필에 대한 여정을 실시간으로(스트리밍 대상의 경우) 또는 다음 배치 평가에서 트리거됩니다. 단일 이벤트와 달리 대상 자격을 사용하면 새로운 이벤트를 전송하기 위해 구현을 변경하지 않아도 대상 정의의 전체 기능을 사용하여 복잡한 트리거 논리를 구축할 수 있습니다. [대상 자격 이벤트](../building-journeys/audience-qualification-events.md)에 대해 자세히 알아보세요.

**스키마 요구 사항:** 추가 스키마가 필요하지 않습니다. 이벤트는 Adobe Experience Platform에 이미 빌드된 기존 대상 정의를 사용합니다.

**예:** 고객의 충성도 지출이 골드 계층 임계값을 초과합니다. 이 프로필은 골드 대상자에 적합하며 여정은 자동으로 트리거되고 환영 보상이 전송됩니다.

>[!NOTE]
>
>대상 자격 이벤트가 **관리 > 이벤트**&#x200B;에서 구성되지 않았습니다. 여정의 첫 번째 단계로 여정 캔버스에서 직접 선택됩니다.

## 이벤트 유형 개요 {#event-comparison}

| | 단일 이벤트 | 비즈니스 이벤트 | 대상 자격 이벤트 |
| --- | --- | --- | --- |
| **프로필에 연결되었습니까?** | 예 — 특정 개인의 작업에 의해 트리거됩니다. | 아니오 — 한 사람과 연결되지 않은 외부 발생에 의해 트리거됩니다. | 예 — 프로필이 대상자로 들어오거나 나갈 때 트리거됩니다. |
| **시작 동작** | 한 프로필이 실시간으로 여정에 들어갑니다. | 자동 대상자 읽기 단계를 통해 여러 프로필을 입력합니다. | 대상자 멤버십이 변경되면 한 프로필이 들어갑니다. |
| **일반적인 사용 사례** | 장바구니 포기 복구, 양식 제출, 앱 로그인, 충성도 이정표. | 비행 취소, 재고 보충 경보, 최신 뉴스, 날씨 이벤트. | 종료된 고객 재참여, 충성도 계층 변경, VIP 오프보딩 흐름. |
| **여정 시작 방법** | 이벤트 기반 항목 — 대상자가 필요하지 않습니다. | 비즈니스 이벤트 + 자동 대상자 읽기(Journey Optimizer에서 추가). | 프로필이 정의된 대상에 들어오거나 나갑니다. |
| **여정당 여러 개?** | 예 — 여정 단계에서 여러 단일 이벤트를 들을 수 있습니다. | 아니요 — 여정 당 하나의 비즈니스 이벤트만 시작 위치에 배치됩니다. | 예 — 다른 활동과 결합할 수 있습니다. |
| **이벤트 ID 유형** | 규칙 기반 또는 시스템 생성. | 항상 규칙을 기반으로 합니다. | 이벤트 ID 없음 — 대상 멤버십 평가를 기반으로 합니다. |
| **관리에서 구성되었습니까?** | 예 | 예 | 아니요 — 여정 캔버스에서 직접 선택됩니다. |

>[!NOTE]
>
>여정은 **one** 비즈니스 이벤트만 포함할 수 있으며, 이 이벤트는 첫 번째 활동이어야 합니다. Journey Optimizer은 **대상자 읽기** 활동을 그 뒤에 자동으로 추가하여 해당 이벤트에 의해 트리거된 여정을 받는 프로필을 정의합니다.

## 이벤트 ID 유형 {#event-id-type}

**비즈니스** 이벤트의 경우 이벤트 ID 유형은 항상 규칙을 기반으로 합니다.

**unitary** 이벤트의 경우 두 가지 유형의 이벤트 ID가 있습니다.

* **규칙 기반** 이벤트: 이 유형의 이벤트는 eventID를 생성하지 않습니다. 간단한 표현식 편집기를 사용하면 시스템에서 여정을 트리거할 관련 이벤트를 식별하는 데 사용할 규칙을 간단히 정의할 수 있습니다. 이 규칙은 프로필의 위치 또는 프로필의 장바구니에 추가한 항목 수와 같은 이벤트 페이로드에서 사용할 수 있는 필드를 기반으로 할 수 있습니다.

  >[!CAUTION]
  >
  >상한 설정 규칙은 규칙 기반 이벤트에 대해 정의됩니다. 여정이 처리할 수 있는 적격 이벤트 수를 주어진 조직에 대해 초당 5,000개로 제한합니다. Journey Optimizer SLA에 해당합니다. Journey Optimizer 라이선스 및 [Journey Optimizer 제품 설명](https://helpx.adobe.com/kr/legal/product-descriptions/adobe-journey-optimizer.html){target="_blank"}을 참조하세요.

* **시스템 생성** 이벤트: 이러한 이벤트에는 eventID가 필요합니다. 이 eventID 필드는 이벤트를 만들 때 자동으로 생성됩니다. 이벤트를 푸시하는 시스템은 ID를 생성하지 않아야 하며 페이로드 미리 보기에서 사용할 수 있는 ID를 전달해야 합니다.

>[!NOTE]
>
>스트리밍된 이벤트만 여정을 트리거할 수 있습니다. 다음 **은(는) 여정을 트리거하는 데 사용할 수 없습니다**.
>
>* 일괄 수집된 이벤트
>* **쿼리 서비스**&#x200B;를 통해 삽입된 이벤트
>* 내부 [!DNL Journey Optimizer]개 데이터 세트의 이벤트(메시지 피드백, 전자 메일 추적 등)
>
>스트리밍된 이벤트를 가져올 수 없는 경우 이러한 이벤트를 기반으로 대상을 만들고 대신 **대상 읽기** 활동을 사용하십시오. 세그멘테이션에만 이벤트를 사용하려면 **실시간 고객 프로필**&#x200B;에 대한 데이터 집합을 사용하도록 설정하십시오.

## 선택 방법 {#choose-event-type}

다음 기준을 사용하여 여정에 적합한 이벤트 유형을 선택하십시오. 주요 질문은 다음과 같습니다. **특정 사용자에 대한 작업을 트리거하거나 여러 프로필에 브로드캐스트하고 있습니까?** [여정 유형에 대해 자세히 알아보기](../building-journeys/journey.md#journey-types).

각 이벤트 유형은 특정 여정 패턴에 매핑됩니다.

| 이벤트 유형 | 여정 패턴 |
| --- | --- |
| 단일 이벤트 | 실시간, 단일 프로필 여정 — 사람이 행동할 때 즉시 트리거됩니다. |
| 비즈니스 이벤트 | 브로드캐스트 여정 - 자동 대상자 읽기 단계를 통해 많은 프로필을 타겟팅합니다. |
| 대상 자격 이벤트 | 세그먼트 트리거 여정 — 프로필이 대상자에 들어오거나 나갈 때 실행됩니다 |

* 트리거가 특정 개인(예: 구매, 양식 제출 또는 충성도 마일스톤)에 연결된 경우 **단일 이벤트를 선택합니다**. 단일 이벤트에는 스키마에서 개인 기반 기본 ID가 필요하며 해당 프로필에 대해 즉시 여정을 시작합니다. [단일 이벤트를 구성하는 방법을 알아봅니다](../event/about-creating.md).

* 트리거가 전 세계적으로 발생(예: 제품 재고, 가격 하락 또는 비행 취소)하고 해당 신호와 관련된 프로필 집합으로 브로드캐스트하려는 경우 **비즈니스 이벤트를 선택합니다**. 비즈니스 이벤트는 여정의 첫 번째 단계여야 하며 **대상자 읽기** 활동을 통해 프로필을 자동으로 타깃팅합니다. 비사용자 기본 ID와 `_id` 및 `timestamp` 필드가 있는 시계열 스키마가 필요합니다. 15분에서 최대 1시간까지 대상 내보내기 지연을 계획합니다. [비즈니스 이벤트를 구성하는 방법에 대해 알아보세요](../event/about-creating-business.md).

* **대상 자격 이벤트를 선택합니다** 트리거가 대상을 입력하거나 종료하는 프로필이고 단일 이벤트에서 제공할 수 있는 것보다 더 복잡한 세분화 논리가 필요합니다. 예를 들어 지출 임계값을 방금 충족한 소멸된 고객을 다시 참여시키거나 VIP 구성원이 충성도 계층에서 나갈 때 오프보딩 흐름을 트리거하는 등의 작업이 여기에 해당합니다. [대상 자격 이벤트에 대해 자세히 알아보기](../building-journeys/audience-qualification-events.md).

>[!CAUTION]
>
>비즈니스 이벤트는 단일 이벤트 또는 대상 자격 활동과 동일한 여정에서 사용할 수 없습니다.

## 키 제한 {#key-constraints}

이 요약을 사용하여 이벤트를 구성하기 전에 구현을 계획합니다.

| 제한 | 세부 사항 |
| --- | --- |
| 처리량 제한 | 모든 샌드박스(단일 및 대상 읽기 여정)에서 조직당 초당 5,000개의 이벤트 |
| 재진입 차단 | 단일 여정 트리거 후 5분 동안 프로필 재입장이 차단됨 |
| 여정 당 비즈니스 이벤트 | 최대 1이며, 첫 번째 단계여야 합니다. |
| 비즈니스 + 단일 여정을 하나로 혼합 | 지원되지 않음 |
| 일괄 처리 이벤트 | 여정을 트리거할 수 없습니다. 대신 **대상자 읽기** 활동을 사용하십시오. |
| 대상 자격 — 관리 | **관리 > 이벤트**&#x200B;에서 구성되지 않음 — 여정 캔버스에서 직접 선택됨 |
| 라이브 이벤트 편집 | 이름, 설명을 변경하거나 페이로드 필드를 추가할 수만 있습니다. |

## 이벤트가 Journey Optimizer에 도달하는 방법 {#data-cycle}

[Adobe Experience Platform 스트리밍 수집 API](https://experienceleague.adobe.com/docs/experience-platform/xdm/api/getting-started.html?lang=ko){target="_blank"}를 통해 이벤트를 POST 호출로 [!DNL Journey Optimizer]에 보내야 합니다. 페이로드는 XDM 형식을 따라야 하며 이벤트 스키마에 **실시간 고객 프로필**&#x200B;이 활성화되어 있어야 합니다.

인증된 스트리밍 모드와 인증되지 않은 스트리밍 모드가 모두 지원됩니다. 일괄 수집된 내부 [!DNL Journey Optimizer] 데이터 세트(메시지 피드백, 전자 메일 추적 등)의 이벤트와 이벤트는 여정을 트리거하는 데 사용할 수 없습니다. 이러한 사용 사례에 대해서는 **대상자 읽기** 활동을 대신 사용하십시오.


## 이벤트 처리량 제한 {#event-throughput}

Adobe Journey Optimizer에서는 모든 샌드박스에 대해 조직 수준에서 이벤트 유형별로 별도의 처리량 제한을 적용합니다.

* **단일 이벤트**: 초당 5,000개의 이벤트
* **대상 기반 여정 이벤트 읽기**: 초당 5,000개의 이벤트

이 제한은 활성 여정에서 사용되는 모든 여정에 적용되며, 여기에는 **Live**, **시험 실행**, **마감됨** 및 **일시 중지됨**&#x200B;이벤트가 포함됩니다. 한도에 도달하면 새 이벤트가 큐에 추가되고 큐가 제거될 때까지 초당 5,000번으로 처리됩니다.

여정 처리 속도 및 다양한 여정 유형이 처리량에 미치는 영향에 대한 자세한 내용은 [여정 처리 속도에 대한 자세한 정보](../building-journeys/entry-management.md#journey-processing-rate)를 참조하세요.

다음 유형의 이벤트는 이러한 할당량에 대해 계산됩니다.

* **외부 단일 이벤트**: 규칙 기반 이벤트와 시스템 생성 이벤트를 모두 포함합니다. 동일한 원시 이벤트가 여러 규칙 정의에 적합한 경우 일치하는 각 규칙은 할당량에 대한 별도의 이벤트로 계산됩니다.

* **대상 자격 여정**: 동일한 스트리밍 대상을 여러 이벤트에서 사용하는 경우 각 사용량은 별도로 계산됩니다. 예를 들어 두 여정의 대상 자격 활동에서 동일한 대상을 사용하면 두 개의 이벤트가 계산됩니다.

* **반응 이벤트**: 프로필 반응(이메일 열림, 이메일 클릭 등)에 의해 트리거된 이벤트 여정 내.

* **비즈니스 이벤트**: 이벤트가 특정 프로필에 연결되지 않고 비즈니스 관련 이벤트에 연결됩니다.

* **Analytics 이벤트**: 여정을 트리거하기 위해 Adobe Analytics과 [통합](about-analytics.md)을 사용하도록 설정한 경우 이러한 이벤트도 포함됩니다.

* **이벤트 다시 시작**: 일시 중지된 여정에서 프로필이 다시 시작될 때 기술적인 이벤트가 트리거됩니다. [일시 중지된 여정 다시 시작](../building-journeys/journey-pause.md#journey-resume-steps)에 대해 자세히 알아보세요.

* **대기 노드 완료 이벤트**: 프로필이 대기 노드를 종료하면 여정을 다시 시작하기 위한 기술 이벤트가 생성됩니다.

>[!NOTE]
>
>대기 및 다시 시작 이벤트를 제외한 다른 모든 이벤트 유형은 대상 읽기를 기반으로 여정에서 사용할 때 할당량으로 계산됩니다.

## 이벤트 업데이트 및 삭제 {#update-event}


기존 여정이 손상되지 않도록 하기 위해 **초안**, **라이브** 또는 **닫힘** 여정에서 사용되는 이벤트를 편집할 때는 이름, 설명 또는 페이로드 필드만 변경할 수 있습니다.

**Live**, **초안** 또는 **마감됨** 여정에서 사용된 모든 이벤트는 삭제할 수 없습니다. 사용된 이벤트를 삭제하려면 해당 이벤트를 사용하는 여정을 중지하거나 해당 이벤트가 사용되는 초안 여정에서 해당 이벤트를 제거해야 합니다. **[!UICONTROL 사용 위치]** 필드를 확인할 수 있습니다. 특정 이벤트를 사용하는 여정 수가 표시됩니다. **[!UICONTROL 여정 보기]** 버튼을 클릭하여 해당 여정의 목록을 표시할 수 있습니다.

## 자주 묻는 질문 {#faq}

**여러 여정에서 동일한 이벤트를 사용할 수 있습니까?**
예 — 여러 여정이 동일한 이벤트를 동시에 수신할 수 있습니다.

**비즈니스 이벤트와 단일 이벤트를 동일한 여정에 결합할 수 있습니까?**
아니요 — 비즈니스 이벤트는 단일 이벤트 또는 대상 자격 활동과 동일한 여정에서 사용할 수 없습니다.

**대상 자격 이벤트에 대해 구성해야 하는 사항은 무엇입니까?**
아니요 — 대상 자격 이벤트가 **관리 > 이벤트**&#x200B;에서 구성되지 않았습니다. 첫 번째 단계로 여정 캔버스에서 직접 대상자를 선택합니다.

**일괄 수집된 데이터를 사용하여 여정을 트리거할 수 있습니까?**
아니요 — 스트리밍된 이벤트만 여정을 트리거할 수 있습니다. 배치 데이터의 경우 대상을 작성하고 대신 **대상 읽기** 활동을 사용하십시오.

**내 여정이 트리거되지 않습니다. 무엇을 확인해야 합니까?**

* 이벤트 스키마에 **실시간 고객 프로필**&#x200B;이 활성화되어 있는지 확인하십시오.
* 이벤트가 스트리밍되는지 확인합니다. 일괄 수집된 이벤트는 여정을 트리거할 수 없습니다.
* 규칙 기반 이벤트의 경우 규칙 조건이 들어오는 페이로드 필드와 일치하는지 확인하십시오.
* 여정이 **Live** 상태이고 프로필이 항목 조건을 충족하는지 확인하십시오.
